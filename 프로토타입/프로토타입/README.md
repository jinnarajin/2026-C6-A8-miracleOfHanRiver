# 투자·생활비 선택 게임 프로토타입

현재 소스 기준으로 정리한 규칙입니다. 최종 확인: 2026-09-22.
새로 시작한 게임의 실제 화면과 동작을 기준으로 합니다. 코드에 남은 이전 버전의 설정은 아래의 ‘이전 버전과 구분’에서 따로 설명합니다.

## 구성과 실행

설치·로그인 없이 브라우저에서 실행하는 정적 모바일 웹게임입니다. HTML, CSS, JavaScript ES modules로 구성되며 별도 서버 API나 빌드 과정은 없습니다.

`index.html`이 있는 이 폴더에서 실행합니다.

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:4173/`에 접속합니다. 파일을 더블 클릭하는 대신 HTTP로 실행해야 합니다.

- 기본 흐름: 시작 화면 → 선택적 투자 경험 설문 → 1스테이지 → 결과·선택적 회고 → 같은 자산으로 2스테이지 → 누적 결과.
- 선택은 버튼으로 진행합니다. 스와이프 조작은 사용하지 않습니다.
- 상단에는 남은 현금, 예정 생활비, 투자금, 건강을 표시합니다. 각 항목을 누르면 설명을 볼 수 있습니다.
- 선택하면 별도의 결과 확인 화면 없이 다음 사건으로 진행합니다.
- 뒤로·앞으로 버튼으로 선택 전후 상태를 확인할 수 있습니다. 새 선택을 하면 앞으로 이동할 경로는 지워집니다. 앞으로 이동 기록은 새로고침 후 유지되지 않습니다.
- 새로고침하면 같은 브라우저에 저장한 진행을 복원합니다.
- 실제 플레이 소요 시간과 공개 배포 후 모바일 동작은 별도 사용자 검증 대상입니다.

## 1스테이지: 투자금과 생활비 관리

### 시작과 진행

| 항목 | 현재 규칙 |
| --- | --- |
| 기본 시작 현금 | 250만 원 |
| 시작 설문 완료 시 | 250만 원 추가, 총 500만 원으로 시작 |
| 최초 보유 주식 | 0주 |
| 최초 건강 | 80 / 100 |
| 진행 길이 | 실제 플레이하는 사건 16개 |
| 게임 달력 | 2025-05-01부터 사건마다 1주 진행하는 가상 일정 |
| 정기 결제 | 화면상 4·8·12·16번째 턴 |
| 월급 | 정기 결제 턴 진입 시 각각 300만 원, 완주 시 총 1,200만 원 |
| 기본 생활비 | 정기 결제마다 170만 원 |
| 갑작스러운 지출 | 3번째 턴 자동차 수리비 50만 원, 7번째 턴 병원비 50만 원 |

갑작스러운 지출은 그 턴에 즉시 결제합니다. 월급은 다음 턴에 들어오며, 이미 낸 수리비·병원비를 정기 생활비에 다시 합산하지 않습니다.
절약이나 건강 악화 추가 비용이 없을 때 완주 지출은 `170만 원 × 4회 + 50만 원 × 2회 = 780만 원`입니다.

### 투자 선택

- 매수: 현금과 200만 원 중 작은 금액으로 살 수 있는 정수 주식 수를 매수합니다.
- 매도: 보유 주식의 절반을 매도합니다. 홀수 수량은 올림 처리합니다. 보유 주식이 없으면 매도 버튼은 표시하지 않습니다.
- 대기: 현금과 보유 수량을 유지합니다.
- 1주도 살 현금이 없으면 매수할 수 없습니다.
- 리밸런싱 사건에서는 주식 비중을 약 50%로 맞추거나 현재 비중을 유지합니다. 현금과 주식만으로 목표 비중을 계산하며, 친구에게 빌려준 돈은 제외합니다. 정수 주식 수로 맞추므로 정확히 50%가 되지는 않을 수 있습니다.

### 생활비 결제와 절약

- 기본 생활비 170만 원 = 월세 80만 원 + 식비 55만 원 + 교통·통신비 5만 원 + 기타 지출 30만 원.
- 생활비 상세에서 식비를 20만 원 줄일 수 있으며, 건강이 10 감소합니다. 각 정기 결제의 식비를 한 번씩 조정할 수 있습니다.
- 절약으로 건강이 20 미만이 되는 선택은 할 수 없습니다. 결제 전 조정한 항목은 취소할 수 있습니다.
- 새 게임의 즉시 병원비 50만 원은 절약 대상이 아닙니다.
- ‘현금으로 낸다’: 현금이 부족하면 주식을 자동 매도하지 않고 1스테이지가 중도 종료됩니다.
- ‘필요한 만큼 판다’: 부족한 금액을 마련할 최소 정수 주식 수를 올림 계산해 매도한 후 결제합니다. 현금이 충분하면 매도 없이 결제합니다.
- 주식을 모두 팔아도 필요한 금액을 마련하지 못하면 중도 종료됩니다.

### 건강과 친구 대여

- 쉬거나 알림을 끄는 일반 사건 선택은 건강을 10 높이고, 계속 확인하는 선택은 10 낮춥니다. 건강은 0~100 범위입니다.
- 건강이 40 이하가 되면 1스테이지에서 한 번, 다음 정기 결제에 건강 악화 병원비 50만 원이 추가됩니다. 이후 건강이 회복돼도 발생한 비용은 남습니다.
- 건강 수치나 내부의 마음의 여유 수치 자체는 현재 종료 조건이 아닙니다.
- 10번째 턴에 친구가 100만 원 대여를 요청합니다. 현재 화면에서는 거절하거나 100만 원을 빌려줄 수 있습니다. 현금이 부족하면 대여할 수 없습니다.
- 대여금은 받을 돈으로 자산에 포함하지만 현금으로 사용할 수 없습니다. 3턴 뒤인 13번째 턴 진입 시 전액 돌려받습니다.
- 대여금이 남은 채 중도 종료 후 2스테이지로 이동하면 전환 시 회수합니다.

### 종료와 손익

16번째 턴을 마치거나 지출 결제에 실패하면 1스테이지 결과를 표시합니다. 중도 종료한 경우도 남은 자산으로 2스테이지에 진입할 수 있습니다.

- 현재 자산 = 현금 + 주식 수 × 현재 장면 가격 + 미회수 친구 대여금.
- 투자 손익 = 현재 자산 + 이미 낸 지출 − 기본 시작 현금 250만 원 − 모든 지원금 − 받은 월급.
- 시작 설문 지원금은 화면의 ‘시작 자산’에 포함됩니다. 회고·의견 지원금도 투자 손익에서는 제외합니다.
- 정상 완료 시 주식 평가 가격은 100,500원입니다. 중도 종료 시 해당 장면 가격을 사용합니다.

## 2스테이지: 가상 2배 레버리지 상품

### 자산 연결과 가격

- 1스테이지 현금, 삼성전자 보유 수량, 종료 가격, 건강, 누적 지출·월급·지원금과 원본 상태를 이어받습니다. 새 연습 자금을 별도로 지급하지 않습니다.
- 8개 장면으로 진행합니다.
- 삼성전자 가격은 1스테이지 종료 가격을 기준으로 `100 → 110 → 85 → 60 → 60 → 95 → 75 → 105%`로 움직이는 가상 후속 시나리오입니다.
- 가상 레버리지 상품은 1주 10,000원에서 시작하며, 매 턴 삼성전자 가격 변동률의 2배를 직전 상품 가격에 적용합니다. 전체 기간 수익률이 삼성전자 수익률의 정확히 2배가 되는 구조는 아닙니다.
- 현재는 현금으로 상품을 매수합니다. 차입금·이자·담보비율·마진콜 규칙은 사용하지 않습니다.

### 선택과 생활비

- 첫 장면은 지켜보기 또는 레버리지 상품 투자 중 선택합니다.
- 이후 거래 장면에서는 삼성전자 또는 레버리지 상품을 최대 100만 원씩 정수 수량으로 매수할 수 있습니다.
- 매도는 선택한 상품의 보유 수량 전부를 팝니다. 다른 상품의 보유 수량은 유지합니다.
- 거래 장면에서 ‘쉬어 간다’를 선택하면 건강이 15 회복됩니다. 첫 장면·관찰 장면·결제 장면에는 해당 선택이 없습니다.
- 4번째 장면은 관찰 후 다음 장면으로 이동합니다.
- 5·8번째 장면 진입 시 월급 300만 원을 각각 받고 생활비 170만 원을 결제합니다.
- 건강이 40 이하이면 이 스테이지에서 한 번, 다음 결제에 병원비 50만 원이 추가됩니다. 건강을 회복해도 이미 발생한 비용은 남습니다.
- 결제 시 현금이 부족하면 레버리지 상품 → 삼성전자 순서로 필요한 수량을 자동 매도합니다.
- 모두 매도해도 부족하면 지원 화면으로 이동합니다. ‘지원금 받고 계속하기’로 `100만 원과 결제 부족액 중 큰 금액`을 받아 결제를 다시 진행합니다. 이 긴급 지원에는 설문 응답이 필요하지 않습니다.
- 현금 부족이나 가격 하락만으로 2스테이지가 중도 종료되지는 않습니다.

### 누적 결과

마지막 결제 후 1·2스테이지 누적 결과를 표시합니다.

- 남은 순자산 = 현금 + 삼성전자 평가액 + 레버리지 상품 평가액.
- 누적 투자 손익 = 남은 순자산 + 누적 지출 − 최초 시작 자산 − 누적 추가 지원금 − 누적 월급.
- 최초 시작 자산에는 1스테이지 기본 250만 원과 시작 설문 참여 시 받은 250만 원을 포함합니다.
- 결과 화면에서 ‘1스테이지부터 다시 하기’와 ‘이 판의 기록 다운로드’를 제공합니다.

## 설문·회고·지원금

모든 지원금은 게임 안의 가상 자금입니다. 질문의 선택지에 따라 금액을 차등 지급하지 않습니다. 선택적 설문·회고·의견은 완료해야 지원금이 지급되며, ‘나중에 하기’에는 지급하지 않습니다.

| 구분 | 노출 시점 | 지급액·횟수 |
| --- | --- | --- |
| 투자 경험 설문 | 1스테이지 시작 화면 | 250만 원, 한 판 1회 |
| 자금 부족 회고 | 현금이 예정 생활비보다 적거나 매수에 필요한 현금이 부족할 때 | 각 스테이지 500만 원, 스테이지당 1회 |
| 앱에 대한 의견 | 각 스테이지 화면상 8번째 턴 | 각 스테이지 250만 원, 스테이지당 1회 |
| 최종 회고 | 1스테이지 결과 화면 | 250만 원, 1회 |
| 긴급 결제 지원 | 2스테이지에서 상품 매도 후에도 결제 자금이 부족할 때 | 부족액과 100만 원 중 큰 금액, 응답 불필요 |

- 시작 설문은 연령대·성별·실제 투자 경험·투자 기간·주요 종목 또는 섹터·보유 기간의 6개 질문입니다. 일부 항목은 직접 입력할 수 있습니다.
- 회고는 선택 답변과 선택적 메모로 구성되며, 앱 의견은 별도 의견 양식을 사용합니다.
- 1스테이지 선택적 지원금 합계는 최대 1,250만 원입니다. 2스테이지 선택적 지원금은 최대 750만 원이며 긴급 결제 지원은 별도입니다.
- 1스테이지 지원금은 지급 시점과 종류를 기록합니다. 뒤로 이동하면 해당 시점 전의 지원금은 잔액에서 제외되고 다시 도달하면 복원되며, 같은 지원금을 중복 지급하지 않습니다.
- 자금 부족 회고의 중복 참여 제한 등은 브라우저 저장 플래그도 사용합니다. 개발용 전체 리셋과 일반 재시작의 삭제 범위는 아래 설명처럼 다릅니다.

## 저장과 기록

진행 상태와 사용자가 제출한 답변은 `localStorage`에 저장합니다. 서버 전송, 자동 설문 취합, 로그인, 기기 간 동기화, 화면 영상 수집 기능은 없습니다. 행동 분석용 이벤트·체류 시간 기록은 현재 비활성화되어 있으며, 과거 행동 기록은 1스테이지 설문 모듈 초기화 시 제거합니다. 게임 복원용 선택 이력은 유지합니다.

| 저장 키 | 내용 |
| --- | --- |
| `return2025-stage1-v3` | 1스테이지 진행·선택·지출 조정·지원금 |
| `prototype-campaign-stage2-v2` | 2스테이지 진행·답변·되돌리기 상태와 1스테이지 원본 |
| `prototype-research-v1` | 1스테이지 설문·회고·앱 의견 답변 |
| `resource-guide-v2` | 처음 조작 안내 완료 여부 |
| `prototype-feedback-used-stage1` / `prototype-feedback-used-stage2` | 자금 부족 회고 참여 여부 |
| `prototype-app-feedback-stage2` | 2스테이지 앱 의견 참여 여부 |

- 브라우저 사이트 데이터를 삭제하면 저장 내용이 사라집니다. 다른 브라우저·기기·도메인으로 자동 이전되지 않습니다.
- 저장 기능이 차단된 환경에서는 진행 유지가 보장되지 않습니다.
- 2스테이지 결과의 다운로드는 `stage2-record.json`으로 현재 2스테이지 상태와 그 안의 1스테이지 원본을 내보냅니다. 별도 키에 저장된 1스테이지 설문 답변 전체를 합쳐 내보내는 기능은 아닙니다.
- 사용자가 의견을 입력해도 운영자에게 자동 전달되지 않습니다. 사용자 테스트 결과를 모으려면 별도 수집 경로나 내보내기 확장이 필요합니다.

## 개발용 버튼과 재시작

현재 화면에는 개발용 ‘처음부터 리셋’과 ‘1스테이지로 돌아가기’가 표시됩니다. `app.mjs`의 `showDevControls()`에서 생성하며, 아직 제거하지 않은 상태입니다.

- 처음부터 리셋: 현재 1·2스테이지 진행, 1스테이지 설문 답변, 안내 완료 여부, 회고·의견 참여 플래그를 지우고 새로고침합니다. 과거 버전의 모든 저장 키를 일괄 삭제하는 기능은 아닙니다.
- 1스테이지로 돌아가기: 2스테이지 저장을 지우고 기존 1스테이지 상태로 돌아갑니다. 처음부터 시작하는 기능과 다릅니다.
- 일반 결과 화면의 ‘1스테이지부터 다시 하기’: 새 게임으로 돌아가고 회고·의견 참여 제한을 초기화합니다. 기존 1스테이지 설문 답변과 안내 완료 여부는 보존합니다.

## 자료와 계산 가정

- 1스테이지에는 저장된 2025년 삼성전자 과거 종가를 재사용합니다. 실시간 시세는 요청하지 않습니다.
- 게임의 주 단위 달력, 월급, 생활 사건, 인물 대화, 건강 수치는 창작 설정입니다. 게임 날짜와 원래 종가의 거래 날짜는 일치하지 않습니다.
- 화면 가격으로 즉시 거래한다고 가정하며 배당·수수료·세금·실제 주문 체결 과정은 반영하지 않습니다.
- 원본 가격 자료는 `design/samsung-2025-prices.json`에 있습니다.
- `sources.html`은 자료 링크를 제공하지만 일부 게임 규칙·날짜·종료 조건 설명이 이전 버전입니다. 현재 게임 규칙은 이 README와 실제 실행 코드를 기준으로 확인해야 합니다.

## 이전 버전과 구분

- 첫 스테이지는 6·15·17장 구성이 아닌 현재 16턴입니다. `SCENES`에는 호환용으로 제외한 사건 2개가 남아 있어 배열 길이는 18입니다.
- 기본 시작 현금은 500만·1,000만 원이 아닌 250만 원입니다.
- 기본 정기 생활비는 회당 170만 원이며, 월급 300만 원이 4턴마다 들어옵니다.
- 스트레스 100 또는 마음의 여유 0으로 종료하는 규칙은 현재 사용하지 않습니다. 내부 `calm` 계산은 남아 있지만 상단에는 건강을 표시합니다.
- 친구에게 50만 원 빌려주기는 엔진에 남아 있으나 현재 UI에서 숨깁니다.
- 병원비 절약, 과거 추가 지출 합산, 제외된 사건의 전액 매수 등 일부 코드는 예전 저장 상태 복원을 위해 남아 있습니다. 새 게임은 `immediateExpenses: true`를 사용합니다.
- 2스테이지의 `fresh2()`에 있는 150만 원은 독립 엔진 기본값입니다. 실제 통합 플레이에서는 1스테이지 자산을 이어받습니다.
- 예전 차입 방식의 2스테이지 상태는 복원 시 별도 `-credit-backup` 키에 보관될 수 있습니다. 현재 상품 방식과 직접 비교하지 않습니다.
- `index.html`의 소개 메타데이터와 `sources.html` 일부 문구는 아직 이전 버전입니다. 이번 갱신 범위는 README입니다.

## 검증

Node.js가 설치된 환경에서 이 폴더를 기준으로 실행합니다.

```sh
node --test tests/*.test.mjs
```

테스트 파일의 범위:

- `tests/engine.test.mjs`: 1스테이지 거래·생활비·건강·대여·리밸런싱·지원금·저장 복원·이전 규칙 호환 경로.
- `tests/immediate-expenses.test.mjs`: 새 게임의 월급 전 즉시 지출과 중복 청구 방지.
- `tests/stage2.test.mjs`: 매 턴 2배 상품 가격, 상품별 매도, 지원금, 건강 비용, 1스테이지 자산 연결·복원.

이번 README 갱신은 실행 코드와 테스트 내용을 대조한 문서 수정입니다. 현재 셸에서 Node.js를 찾을 수 없어 테스트를 재실행하지 않았으며, 통과를 새로 확인한 것으로 표시하지 않습니다.

GitHub Pages에는 이 폴더의 `index.html`과 참조 파일의 상대 경로를 유지해 게시할 수 있습니다. 공개 전에는 개발용 버튼 처리, 자료 설명의 이전 문구 정리, 모바일 전체 흐름·새로고침·설문 입력·다운로드 동작을 실제 배포 주소에서 확인해야 합니다.
