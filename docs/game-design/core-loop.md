# Loop — 코어 Loop 상세 (결산전 1판) v0.1

- 작성: 엘레나 (초안) · 2026-10-13
- 근거: `game-elements.md`, 시리우스 스토리 바이블 v0.1, 프롤로그
- 표기: `[초안]` UT 후 조정 · `[미정]` 아직 안 정함 · ★ 바이블 고정 규칙

```
[결산전 1판 = 5라운드]
0. 판 준비 → 1. 일기장 확인 → 2. 카드 배정
→ 3. 라운드 × 5 ( ① 브리핑 → ② 포지션 → ③ 작전 → ④ 정산 )
→ 4. 결산 → 5. 개런티 / 패널티 → 6. 복기
```

---

## 0. 판 준비

**화면**: 대전 소개 (상대 일러스트, 이름, 세력, 한 줄 대사)

| 항목 | 값 |
|---|---|
| 형식 | 1:1 (결산전 3만 1:1:1) |
| 판 자금 | 나·상대 모두 **100** ★ 매 판 같은 금액 |
| 종목 시작가 | 반도체 10 · 바이오 10 · 국채 10 |
| 걸린 것 | 승리 시 개런티 `[초안] 20 + 수익률 × 50` / 패배 시 패널티 1 |

**플레이어 액션**: 확인 → "결산전 시작"

**시스템**: 이번 판 **각본 데이터**를 불러온다 (라운드별 뉴스, 상대 포지션, 상대 카드, 정책 이벤트).

---

## 1. 일기장 확인

**화면**: 일기장 펼침. 이번 판 페이지가 자동으로 열린다.

| 결산전 | 일기장에 보이는 것 |
|---|---|
| 결산전 1 | 상대의 라운드별 포지션 전부 + 핵심 사건 1~2개 (예: "4R 바이오 임상 실패") |
| 결산전 2 | 시장 흐름만 (1회차에 없던 대결 → 상대 정보 없음) |
| 결산전 3 | 측근 학생의 포지션 예측 (분석가는 모름) |

**플레이어 액션**: 읽기 → 닫기. 이후 **브리핑 단계에서 언제든 다시 열 수 있다.**

★ 데모(1학기) 동안 일기장은 항상 정확하다.

---

## 2. 카드 배정

**화면**: 카드 3장이 한 장씩 손패로 들어오는 연출.

- 손패 **3장** `[초안]`. 지금까지 **해금된 카드 중에서** 각본으로 정해진 3장을 받는다 (랜덤 아님. UT 재현성 때문).
- 상대도 3장을 받는다. 상대 손패는 뒷면만 보인다.

**플레이어 액션**: 카드 길게 누르면 효과 설명. 확인 → 1라운드로.

---

## 3. 라운드 (× 5)

> **포지션 규칙** `[초안]`: 포지션은 **그 라운드 정산 때 자동 청산**된다. 매 라운드 새로 건다.
> 가격은 라운드가 지나도 이어진다. 라운드를 넘어 포지션을 보유하는 방식은 개발량이 커서 데모에서 뺀다.

### ① 브리핑: 읽는다

**화면**: 시세판(3종목 현재가 + 지난 라운드 변동) · 공개 뉴스 1장 · 엎어진 비공개 뉴스 1장 · 라운드 표시(2/5) · 내/상대 판 자금

**시스템**
1. 이번 라운드 공개 뉴스를 앞면으로 띄운다.
2. 비공개 뉴스를 뒷면으로 띄운다.
3. 이번 라운드에 정책 이벤트가 있으면 "중앙은행 발표 예정" 배지를 띄운다.

**플레이어 액션**
| 액션 | 설명 |
|---|---|
| 공개 뉴스 읽기 | 어느 종목에 어떤 방향인지 문장으로만 보인다 (수치는 숨김) |
| 일기장 열기 | 이번 라운드 1회차 기록 확인 |
| 정보원 카드 쓰기 | ★예외: 정보원만 브리핑에 쓸 수 있다. 비공개 뉴스 미리 보기 또는 상대 포지션 1개 미리 보기 |
| "포지션 잡기" | 다음 단계로 |

### ② 포지션: 건다

**화면**: 종목 3줄. 각 줄에 방향 버튼 · 금액 슬라이더 · 레버리지 버튼 · 마진콜 가격선 표시

**플레이어 액션** (종목마다)
| 입력 | 선택지 | 제약 |
|---|---|---|
| 방향 | 매수 / 공매도 / 관망 | 공매도는 결산전 1 클리어 후 해금 |
| 금액 | 10 단위 슬라이더 | 세 종목 합계 ≤ 현재 판 자금. 나머지는 현금 |
| 레버리지 | 1 · 2 · 3 · 5배 | 해금 단계에 따라 3배까지 |

- 레버리지를 고르면 **마진콜 가격**을 바로 보여준다: `마진콜 변동률 = 1 ÷ 레버리지` (5배면 20% 반대로 움직이면 마진콜)
- "포지션 공개" → 확인 팝업 → 확정

**시스템**
1. 플레이어 포지션 확정 (이번 라운드 수정 불가)
2. 상대 포지션을 각본에서 꺼낸다
3. **동시 공개 연출**: 양쪽 포지션 카드가 동시에 뒤집힌다

### ③ 작전: 흔든다

**화면**: 손패 · 공개된 양쪽 포지션 · 시세판 · 카드 상점 버튼

**플레이어 액션**
| 액션 | 설명 | 제약 |
|---|---|---|
| 카드 사기 | 운용 자산으로 카드 1장 구매 (상점에 2~3장 제시) | 비용 `[초안] 10`. 판당 2회. 자산 동결 중이면 불가 |
| 카드 쓰기 | 카드 1장 선택 → 대상 종목 선택 → 확정 | **라운드당 1장** |
| 넘기기 | 카드 아끼기 | 남은 카드는 다음 라운드로 |

**시스템**
1. 플레이어 카드 확정
2. 상대 카드를 각본에서 꺼낸다
3. **동시 공개**: 양쪽 카드가 뒤집힌다 (효과는 아직 반영 안 함)

### ④ 정산: 확인한다

**화면**: 연출 위주. 탭으로 한 단계씩 넘긴다.

**시스템 처리 순서** (이 순서대로 연출)
1. **비공개 뉴스 공개**: 뒤집히는 연출
2. **효과 합산**: 종목마다 `변동률 = 공개 뉴스 + 비공개 뉴스 + 카드 효과 + 정책 효과`
3. **새 가격**: `새 가격 = 이전 가격 × (1 + 변동률)`, 하한 1. 시세판 숫자가 크게 바뀌는 연출
4. **손익 계산** (나·상대 각각, 포지션마다)
   - 매수: `손익 = 투입액 × 레버리지 × 변동률`
   - 공매도: `손익 = 투입액 × 레버리지 × (−변동률)`
5. **마진콜 체크**: `손실 ≥ 투입액`이면 마진콜
   - 손실은 투입액까지만 (`손익 = −투입액`)
   - 빨간 경고 + 강제 청산 연출 + 상대 반응 대사
6. **판 자금 갱신**: `판 자금 = 판 자금 + 모든 손익`
7. **KO 체크**: 판 자금 ≤ 0이면 즉시 **KO 패배** → 4. 결산으로
8. **라운드 요약**: 나 vs 상대 수익률 막대, "다음 라운드" 버튼

**플레이어 액션**: 탭으로 넘기기. 결정은 없다.

5라운드가 끝나면 → 4. 결산

---

## 4. 결산

**시스템**
- `수익률 = (최종 판 자금 − 100) ÷ 100`
- 수익률이 높은 쪽이 승리. KO된 쪽은 무조건 패배.
- 동률 `[초안]`: 무승부. 개런티·패널티 없음.
- 1:1:1: 1위만 승리. 2·3위 모두 패널티.

**화면**: 최종 수익률 비교 → 승리/패배 연출 → 상대 대사 (바이블 말투 예시)

---

## 5. 개런티 / 패널티

| 결과 | 처리 |
|---|---|
| 승리 | 운용 자산 += 개런티 `[초안] 20 + 수익률 × 50` |
| 패배 | 패널티 포인트 +1 → 1: 성적 하락 / 2: 자산 동결 / 3: 퇴학(게임 오버) |
| 무승부 | 없음 |

---

## 6. 복기

**화면**: 라운드별 한 줄 기록
> "3R · 바이오 공매도 30 × 3배 · 근거: 일기장(상대 바이오 몰빵) · 결과 +36"

- 챌린지 리스폰스("결정의 이유를 설명할 수 있는 투자자")와 연결되는 화면.
- `[미정]` 포지션 확정 때 "근거" 태그(뉴스 / 일기장 / 감)를 고르게 할지. 고르게 하면 복기가 풍부해지지만 결정 수가 늘어난다.

"계속" → 메타 Loop (성적표 → 성장 → 중앙은행 → 정책 발표 → 다음 결산전)

---

## 7. 예시: 결산전 1, 2라운드

| 단계 | 내용 |
|---|---|
| 브리핑 | 공개: "바이오 신약 임상 결과 다음 주 발표" / 비공개: ??? / 일기장: "상대 2R 바이오 매수 60 × 3배" |
| 포지션 | 나: 반도체 매수 40 × 1배 · 바이오 관망 / 상대: 바이오 매수 60 × 3배 (동시 공개) |
| 작전 | 나: 악재 루머 → 바이오 / 상대: 호재 루머 → 바이오 |
| 정산 | 비공개 뉴스: "임상 지연" 바이오 −30% · 공개 뉴스 +5% · 루머 +10% −10% → **바이오 −25%**, 반도체 +5% |
| 손익 | 나: 40 × 1 × 5% = **+2** / 상대: 60 × 3 × (−25%) = −45 → **판 자금 100 → 55** |
| 요약 | 나 102 (+2%) vs 상대 55 (−45%) |

## 8. 개발용 정리

### 상태 (enum)
```
intro → diary → deal
→ round(n): briefing → position → operation → settlement
→ (n < 5 && !KO) ? round(n+1) : result
→ reward → review → exit
```

### 각본 데이터 (JSON 예시)
```json
{
  "id": "match1",
  "format": "1v1",
  "opponent": "noble_student",
  "hand": ["rumor_up", "rumor_down", "rumor_down"],
  "diary": ["상대는 2R에 바이오 매수 60 × 3배", "4R 바이오 임상 실패"],
  "rounds": [
    {
      "public":  { "text": "바이오 신약 임상 결과 다음 주 발표", "effect": { "bio": 0.05 } },
      "hidden":  { "text": "임상 지연", "effect": { "bio": -0.30 } },
      "policy":  null,
      "opponent": {
        "positions": [{ "stock": "bio", "side": "long", "amount": 60, "leverage": 3 }],
        "card": { "id": "rumor_up", "target": "bio" }
      }
    }
  ]
}
```
- 시리우스는 `text`, `diary`를, 엘레나는 `effect` 수치를 채운다.

### 엔진 함수 (화면과 분리, XCTest)
- `applyRound(state, playerInput, script) -> (newState, events)`
- `events`는 연출 순서대로: 비공개 공개 → 가격 변동 → 손익 → 마진콜 → KO

## 9. 정해야 할 것

1. 포지션을 라운드마다 청산하는 방식으로 갈지 (보유 방식보다 단순)
2. 정보원 카드만 브리핑 단계 사용 허용
3. 동률 처리 = 무승부
4. 복기의 "근거 태그"를 넣을지
5. 손패 3장, 카드 구매 비용 10, 판당 2회 등 `[초안]` 수치
